# Pokhara Landsat 5: Seasonal Land Surface Temperature and Spectral Indices (2004)

**Original Google Earth Engine JavaScript workflow by Bijesh Shrestha**  
**Research institution:** Pashchimanchal Campus, Institute of Engineering (IOE), Nepal  
**Related thesis:** *Study on Urban Land Surface Temperature Using Remote Sensing and CA-ANN in Pokhara, Nepal*


## Project summary

The workflow analyzes Landsat 5 Collection 2 Tier 1 Level 2 surface reflectance and surface temperature data for Pokhara, Nepal. It produces a seasonal mean using strict scene cloud-cover filtering and fills remaining gaps using more permissive same-year images, corresponding seasonal windows from 2003/2005, and optionally neighboring pixels. It also prepares summary tables, a grid-sampled dataset and raster export tasks.

| Setting | Value in the original code |
| --- | --- |
| Study area | Pokhara boundary stored as an Earth Engine FeatureCollection asset |
| Primary analysis window | **May 1–August 30, 2004**, inclusive |
| Landsat dataset | `LANDSAT/LT05/C02/T1_L2` |
| Processing level | `L2SP` (surface reflectance + temperature) |
| Primary scene cloud-cover limit | 20% |
| Fallback scene cloud-cover limit | 50% |
| Adjacent-year fallback windows | Same dates in 2003 and 2005 |
| Spatial sampling interval | Approximately 300 m, using latitude/longitude conversion |
| Export scale | 30 m (not 30 m native thermal resolving power) |
| Optional local gap fill | Enabled, focal mean radius 1 pixel |
| Variables | LST (°C), NDVI, NDWI (green/NIR), NDBI |

**Important:** The final patched raster is **not a purely observed 2004 composite**: some values can be taken from the 2003/2005 fallback composite or generated by local smoothing. Do not treat all filled pixels as directly measured 2004 temperatures.

## Run the comment-polished original GEE script

1. Open [Google Earth Engine Code Editor](https://code.earthengine.google.com/).
2. Open [`scripts/landsat5_pokhara_2004.js`](scripts/landsat5_pokhara_2004.js) and paste it into a new Earth Engine script.
3. Ensure you have permission to use the boundary asset referenced near the beginning of the script: `projects/learnpokharalst/assets/boundary/Pokhara`. If necessary, change **your local copy** to an accessible boundary asset. The repository version deliberately preserves the original executable logic.
4. Review the dates, cloud thresholds, fallback strategy, gap-fill option and export folder. Run the script.
5. Inspect printed image counts, ROI coverage statistics, layer displays and export task definitions. In the **Tasks** tab, launch the desired export tasks manually.
6. Inspect the exported maps and data for validity before citing measurements or publishing figures.

See [the step-by-step GEE instructions](docs/RUN_IN_GEE.md) and [scientific limitations](docs/LIMITATIONS.md).

## Main calculations

- **LST (°C):** scaled USGS `ST_B6` surface-temperature product converted from kelvin to Celsius: `ST_B6 × 0.00341802 + 149.0 − 273.15`.
- **NDVI:** `(SR_B4 − SR_B3) / (SR_B4 + SR_B3)` (near infrared / red).
- **NDWI:** `(SR_B2 − SR_B4) / (SR_B2 + SR_B4)` (green / near infrared; McFeeters-style water index).
- **NDBI:** `(SR_B5 − SR_B4) / (SR_B5 + SR_B4)` (SWIR1 / near infrared).

Reflectance bands are scaled using `DN × 0.0000275 − 0.2`. These are USGS-provided Level 2 surface temperature data; the code does **not** derive surface temperature from raw radiance using a new atmospheric correction model.

## Exports specified by the script

The script defines **six CSV exports**: primary-image metadata, primary-image per-scene ROI statistics, patch-source metadata, patch-source per-scene ROI statistics, one summary table and a final grid-sample table.

It also defines **four patched composite GeoTIFF exports** (LST, NDVI, NDWI, NDBI). With `exportPrimaryIndividualTIFFs = true`, the script creates three additional raster export tasks per primary image (LST, NDVI, NDBI). Export tasks must be manually started in Earth Engine; no outputs are included in this repository.

## Interpretation and limitations

- The scene-level cloud threshold is not the same as percent cloud-free area within the Pokhara boundary.
- The `QA_PIXEL` mask uses bits 0–4 and does not explicitly mask snow/ice (bit 5).
- `normalizedDifference()` can mask valid scaled reflectance pixels when an input is negative.
- Adjacent-year and focal-mean gap filling modify provenance and add uncertainty; **there is no pixel-wise source tracking in the original script**.
- LST exported at 30 m should not be described as 30 m independent native thermal measurements.
- Grid spacing is approximate, not built from a projected metric grid.
- Results and numerical findings have not been supplied for this repository. Nothing here validates the CA-ANN thesis model.

Read [full methodology](docs/METHODOLOGY.md) and [limitations](docs/LIMITATIONS.md) before reusing the analysis.
